Why another mock

Your backend still runs its real OIDC client: discovery, PKCE, code exchange and ID-token verification. Only the human with a Google account is replaced.

Any email signs in

No user list to keep in sync with your tests. List users only when you want buttons, fixed ids or names.

Stable identities

An email without an id gets a SHA-256-derived UUID, identical on every restart and every machine.

Stable signing key

The RSA key comes from a seed, so restarting the mock never invalidates the keys your backend cached.

One issuer, two hosts

Keep iss as your backend sees it and serve the browser from another host. No /etc/hosts edits.

Strict where it matters

PKCE S256 is mandatory, codes are single-use, and a wrong verifier or redirect gets invalid_grant.

Tested with a real client

The test suite drives the full flow with the Rust openidconnect crate.

Quick start

Pull from Docker Hub (amd64 and arm64) and run it. Point your client at http://localhost:5556 with local-client / local-secret.

docker run --rm -p 5556:5556 -e USERS=alice@example.test,bob@example.test curroya/oauth2-mock

docker compose

services:
  oidc:
    image: curroya/oauth2-mock
    ports: ["5556:5556"]
    environment:
      ISSUER: http://oidc:5556
      BROWSER_BASE_URL: http://localhost:5556
      CLIENT_ID: my-app
      CLIENT_SECRET: my-app-secret
      USERS_FILE: /users.json
    volumes:
      - ./users.json:/users.json:ro

The flow

Standard authorization code with PKCE. Nothing your client does is skipped.

  1. DiscoverYour backend reads /.well-known/openid-configuration and /keys.
  2. AuthorizeThe browser lands on /auth with a S256 challenge, nonce and state.
  3. Pick a userA click, a typed email, or login_hint redirects back with a single-use code.
  4. Exchange/token checks the client, redirect and verifier, then returns a signed ID token.

In end-to-end tests

Every email is a stable identity, so give each parallel worker its own address. No fixture list required.

// click a configured user
await page.getByRole('button', { name: /candidate@example\.test/ }).click()

// or sign in as anyone
await page.getByLabel('Email').fill(`worker-${workerIndex}@example.test`)
await page.getByRole('button', { name: 'Sign in' }).click()
